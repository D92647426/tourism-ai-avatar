# 景区数字人课设创意方向

日期：2026-10-14。状态：设计提案，尚未实现。用户明确课程重点为开源软件的创意设计，角色资产制作后置。

## 1. 设计判断

以一个能够让同学现场体验的新交互作为课设主线，基础问答、地图和后台支撑该体验。创意贡献应相对于采用的开源底座明确说明；这里不声称行业首创，也不预估教师分数。

已核实的参照：

- [Museum-AI 项目](https://github.com/Aby5s/Museum-AI)已包含知识图谱、向量检索和多智能体等能力，说明单纯增加这些技术名词难以说明本组的交互贡献。
- [文化遗产位置游戏研究](https://www.mdpi.com/2414-4088/6/5/36)涉及叙事、角色扮演和寻宝，任务打卡本身已有先例。
- [Vanderbilt Teachable Agents](https://www.vanderbilt.edu/oele/teachable-agents/)研究通过教会软件角色来支持学习。下面把该交互思路用于景区观察和角色陪伴，是本课设的设计提议；实际体验和学习效果需要本项目验证。

## 2. 候选方向

| 方向 | 游客体验 | 可见的设计贡献 | 首版工作量判断 |
|---|---|---|---|
| 今天你当导游 | 游客带初来陆地的小鲸认识景区，通过观察、解释和对照资料教会她；后续站点会引用之前学过的内容 | 可教的数字人、观察证据、概念记忆、后续行为变化 | 中，优先推荐 |
| 双人拼图游 | 两位游客分别获得不同观察线索，通过交流拼出解释；AI 根据全队证据提供分级提示 | 信息互补的协作、共享证据板、团队提示策略 | 中高，需要房间和多人状态 |
| 同景异时 | 同一地点切换不同年代或角色的讲述视角，对照历史资料、修建目的与今天的使用 | 时间轴、角色视角切换、事实与剧情逐条对应 | 中，主要成本在内容考据 |
| 全队都愿意走的路线 | 每位同伴填写喜好与限制，系统展示路线照顾了谁、如何取舍；有人累了后现场调整 | 共同决策、约束可视化、可解释的方案比较 | 中，适合强调实用价值 |
| 景区内容导演台 | 社区将景点、知识依据、观察任务、角色台词和解锁条件制作成可分享内容包 | 可复用开放内容规范、校验工具与作者创作流程 | 首版中，完整可视化编辑器较高 |

以上工作量均为相对判断，未掌握小组人数、期限和美术能力，不能据此承诺工期。

## 3. 推荐主线：鲸游记——今天，你来当导游

### 角色设定

小鲸来自海洋，第一次来到陆地景区。她能帮助游客查资料、理解提示，也需要游客观察眼前细节、向她解释。游客的解释经过景区资料核对后，进入本次旅程的概念记忆。

### 一段可演示的体验

以下为交互示例，具体问题须按真实景点与资料制作。

1. 到达某个建筑点位，小鲸邀请游客找两处能够说明建筑特色的细节。
2. 游客选择画面热点，或用一句话描述自己的发现。
3. 小鲸结合已审核观察任务和资料判断是否有依据；信息不足时给局部提示，再邀请游客补充。
4. 游客完成解释后，界面增加一张“你教会我的知识卡”，显示观察位置、解释和资料出处。
5. 到下一站，相同概念再次出现，小鲸主动应用上一站的知识，游客可补充或纠正。
6. 结束时展示双方共同完成的探索地图，以及小鲸能复述的三项知识。

### 核心机制

- 每个景点配置观察热点、概念、可接受证据、来源和三级提示。
- 用结构化旅程记忆记录 `concept_id`、`evidence_id`、游客解释与核对状态；后续站点依据记忆选择问题。
- 任务状态由后端推进，模型负责自然对话与受资料约束的反馈。
- 游客的自由描述保存在本次旅程；公共景区知识的新增仍走现有资料审核发布流程。
- 角色的“学会”通过知识卡、概念关系与后续行为变化表现，不依赖重新训练模型。

### 第一版范围

一个景区、三个景点、六个观察任务、一份旅程记忆和一个结束回顾页。支持在课堂点击地图切换地点、使用预置景点图片完成体验。

### 开源贡献

定义可导入的景区探索内容包，包含景点、知识出处、观察热点、任务、概念和提示。先交付示例内容包及校验器，后续可增加编辑界面，让其他开发者替换内容复用。

### 效果验证

邀请同学分别体验基础问答模式和探索模式，记录发现细节数量、主动解释次数、完成情况、知识回忆和主观体验。小样本体验用于发现设计问题；学习提升的结论应基于实际测量。
