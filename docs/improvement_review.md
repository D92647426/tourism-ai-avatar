## 建议的原创体验：今天你当导游

1. 在一处景点领取观察任务，例如寻找图案、比较形态、解释一个细节。
2. 游客用文字或语音向数字人讲述发现，数字人结合任务资料给出反馈与追问。
3. 已确认的发现记入当前旅程，后续能引用；结束生成包含本人观察和资料出处的游记卡。
4. 事实、景区传说和模型推测分开展示。游客新说法作为待核验记录，不自动进入公共知识库。
5. “教会她”指旅程记忆和经审核的内容贡献，不声称训练或更新模型参数。

首版仅制作 3 个景点，每个 1 个经过核对的任务。支持手动选点或现场二维码，教室演示不依赖 GPS。先做文字与现有数字人互动，再加入语音。

三分钟验收：
- 选择景点并领取任务；
- 回答后得到引用任务资料的反馈；
- 后续追问能记住本次发现；
- 生成真实反映本次操作的旅程卡。

## 将开源复用做成可以展示的能力

景区内容包使用可校验的 JSON 格式，包含景点、别名、任务、评价要点、资料出处、台词和作者/素材授权信息。支持预览、校验、导入和导出；缺字段或资源失效时明确报错。

答辩可导入另一份小型内容包，展示无需改 Java 代码即可更换景点和任务。它扩展的是内容层，角色资产另行配置，不承诺任意 3D/Live2D 模型通用。

## 三人分工与实施顺序

| 成员 | 可独立负责的成果 | 共享接口 |
|---|---|---|
| A | 游客旅程界面、任务交互、数字人状态、旅程卡 | 任务与会话响应结构 |
| B | 会话隔离、知识检索、依据返回、任务反馈 | 景点 ID、会话 ID、任务 ID、来源 ID |
| C | 内容包格式/导入导出、管理端、资料整理与演示验收 | 内容版本、验证错误、任务样例 |

顺序：
1. 修复管理权限与密码响应，纠正演示统计；增加对应验收。
2. 跑通一个景点的完整任务流程，确认反馈和来源。
3. 扩展到三个景点，打通内容包和旅程卡。
4. 完善语音与形象，完成三人真实使用演示。

不建议首版同时展开复杂 3D 建模、实时多人、全景区导航与独立原生 App。若加入路线协商，应作为后续扩展并使用可核对的景区数据。

## 课设证据

保留继承功能与新增功能对照、原版/新版任务对比、三位成员的有效 PR、少量真实试用反馈。可比较完成任务时间、追问正确关联率、带依据回答比例和内容包导入结果；这些是建议采集的指标，当前没有实测成绩。
