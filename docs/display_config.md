# REQ-038 展示设置在游客端生效（GitHub #8）

## 目标与方案

管理员保存导游名称、首次欢迎语和主题色后，游客刷新即生效；读取失败保持稳定默认显示，已有聊天不被迟到配置改写。基于认证PR #15，继续使用公开只读 GET /api/digital-human-config；管理 GET/PUT 仍需ADMIN及写请求CSRF。语音播放参数消费留给 #14，本轮不换模型或声音服务。

用户持续授权按议题开工，沿用当前checkout和独立分支。2026-10-29 决定交办时300分钟额度usedPercent=42，剩余58%，按新规则启用DeepSeek；Codex定方案、界面及验收，DeepSeek只实现明确后端部分。

## API-038 与保存规则

- 保留现有7个配置字段和公开接口，不公开用户/凭据。PUT /api/admin/digital-human-config 接受JSON对象的部分更新：缺字段保持原值，null/未知字段/类型错误/非法值返回400，整次拒绝不部分改写。
- name为trim后1–40字符且无控制字符；welcomeMessage为trim后1–500字符，允许换行/制表但不接受其他控制字符。文本可含类似HTML的字面内容，页面只能textContent渲染。
- primaryColor只接受#RRGGBB六位十六进制，保存为小写；拒绝url()/CSS注入/命名色/缩写色。voiceType与modelName若提供，须非空字符串且无控制字符，最长分别200/100字符；volume有限数0–1，speechRate有限数0.5–2；不隐式把音量0改1。这些参数本轮仅安全保存，不声称游客端已消费。
- 同一把锁保护读取快照/更新。校验候选→同目录临时文件→原子替换（平台不支持时替换移动）→发布内存快照；失败HTTP500 code=CONFIG_SAVE_FAILED，旧内存不变，不返回路径/凭据，不能假称保存成功。返回配置副本，外部不能直接改内存。
- 缺文件可写默认配置；已有坏文件/非法字段启动时降级默认并记录警告，不覆盖原文件。缺字段默认值沿用DigitalHumanConfig，读取路径可无父目录。非法字段可以整份回退默认，不对外谎称已持久化修复。

## 游客页面与后台交互

- GuideDisplayConfig独立脚本负责只读fetch、逐字段默认/校验、主题派生和DOM应用。公开读取最多等待5秒（含JSON解析）；失败或格式不合法保持默认，不阻止游客看景点、输入或读回答。
- 导游名称同时更新人物标签/聊天头。首次欢迎气泡独立ID，仅在没有开始发送聊天时更新；发送后迟到配置可更新名称/颜色，但不能改写欢迎气泡或其他聊天内容。不自动播报欢迎语。
- 默认名称/欢迎语/颜色与DigitalHumanConfig一致。主题应用既有CSS变量到页头、聊天头、悬浮入口、发送按钮与用户气泡，保持原布局；根据色值派生深浅色和可读前景色，不把任意字符串塞进CSS。
- 后台配置加载失败明确提示并禁止从未加载的默认表单直接保存；成功加载后才能编辑。保存时按钮防重复，检查HTTP状态，只有收到匹配的成功配置才提示成功并显示服务端标准化结果。失败保留输入、显示可操作错误。保留音量0，避免编辑名称时改掉其他设置。
- 可用status提示“保存后游客刷新生效”，不显示实现细节或假称真实语音已改变。
