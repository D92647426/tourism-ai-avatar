# 开源创意选型：景区推理剧场

核查日期：2026-11-02。交付类型：研究与实施计划；本轮未安装以下引擎，也未实现 AR、剧情或多人同步。官方能力与团队建议分开陈述。不是课程分数承诺。

## 结论与主次

推荐主线是“景区推理剧场”：游客扮演观察员或资料员，从线索中提出解释、核对依据，数字人追问，结束后回放选择如何改变了观察路径。先做 inkjs 单设备故事闭环，再把 MindAR 作为实体卡片入口；其他引擎按素材与真实需求再引入。

创意归属在小组设计的“观察—推测—证据—修订—回放”机制、原创内容包和数字人衔接。底层分支运行、图像跟踪和同步算法归上游；不能把换皮或拼库描述为自研引擎。小组共同选题仍由 #1 确认。

现有能力已经提供较好的底座：[观察玩法](../exploration_design.md#L3)、[内容包与讲解搭档](../exploration_coach_design.md#L1)。PR #32 的游览导演、观察辅助与新界面已合入 main（a40f763）；故事本体也可单独验证，不把编排路线当成真实导航。

## 五个候选与实际玩法

以下“难度/顺序”是结合本项目原生 JS、三人团队及素材情况的工程判断，不是上游项目性能结论。

| 优先级 | 官方开源项目 | 能提供的基础能力 | 我们设计的体验 | 主要成本与取舍 |
|---|---|---|---|---|
| P0 主线 | [inkjs](https://github.com/y-lohse/inkjs) / [ink](https://github.com/inkle/ink) | 文本、变量、分支选择、故事状态 | 同一景点，两种角色的问题不同；选择证据后可修订结论，回放分歧 | 中；剧本质量比引擎更关键，先限制为一幕三节点 |
| P1 展示亮点 | [MindAR](https://github.com/hiukim/mind-ar-js) | 浏览器对预制图像目标的跟踪与叠加 | 手机扫描原创线索卡，浮出观察框/证据提示，点击才加入故事 | 中高；摄像头、WebGL、真机光照、HTTPS，必须有手动入口 |
| P2 扩展 | [Yjs](https://github.com/yjs/yjs) | 共享数据与冲突合并 | 两人各收集线索，在共享证据板标“观察/推测/待核对”，合成讲解 | 高；同步、房间鉴权、持久化都要另做，先验证多人是否必要 |
| 条件候选 | [Pannellum](https://github.com/mpetroff/pannellum) | 全景查看、热点与场景切换 | 教室内寻找场景细节，热点交接同一套故事线索 | 渲染接入较低，素材成本高；有自摄/明确授权的全景再做 |
| 暂缓 | [Transformers.js](https://github.com/huggingface/transformers.js) | 浏览器运行文本/视觉/语音等模型 | 可研究离线语音转文字或线索语义检索 | 模型下载、准确率和移动性能要实测；暂未选模型，不承诺离线准确识景 |

inkjs 的 [README](https://github.com/y-lohse/inkjs#readme) 提供浏览器 Story、Continue、currentChoices 使用方式，许可为 [MIT](https://github.com/y-lohse/inkjs/blob/master/LICENSE.md)。MindAR 的图像跟踪与 GPU/worker 使用见 [README](https://github.com/hiukim/mind-ar-js#readme)，图像目标编译、设备和许可证详见 [一手源核查](2026-11-02-ar-story-panorama-sources.md#L1)。Pannellum 的 [官方场景切换示例](https://pannellum.org/documentation/examples/tour/) 支持全景串联；不能据此声称自动重建真实景区。

Yjs 的 [官方 README](https://github.com/yjs/yjs#readme) 描述共享类型，核心 [MIT 许可](https://github.com/yjs/yjs/blob/main/LICENSE)；[y-websocket 官方文档](https://docs.yjs.dev/ecosystem/connection-provider/y-websocket) 明确采用客户端—服务器模式、交换更新与 awareness，可接鉴权。它不会自动继承本项目的 Spring Session，也不直接解决业务权限。正式使用还需核对锁定版本与 provider 依赖的许可。

Transformers.js 库为 [Apache-2.0](https://github.com/huggingface/transformers.js/blob/main/LICENSE)，[官方能力说明](https://huggingface.co/docs/transformers.js/v3.8.1/en/index) 包含多模态任务；[自托管指南](https://huggingface.co/docs/transformers.js/en/custom_usage) 说明默认远端模型/WASM 与本地配置。因此“浏览器运行”不等于首次打开无需联网，库许可也不代表任何模型权重都可任意分发。选模型后再核对模型卡、体积、中文表现与目标手机。

## 一个能演示的原创故事

工作名：“一张导览卡的真相”。角色和任务冲突为原创课堂情境，任何虚构台词显式标作剧情；不补写景区历史人物的真实言论。

1. 开场：数字人请游客帮助修改一张尚未核实的导览卡。选“观察员”先看外观线索，选“资料员”先看一段带来源/状态的资料。同一设备角色切换不是多人隐藏信息。
2. 选择：可以“继续观察细节”“打开资料核对”“暂不下结论”。每条路径至少引出一个不同问题或证据；同一个按钮换台词不算分支完成。
3. 提交：游客写“我看到什么 / 我推测什么 / 还缺什么证据”，数字人通过现有显式草稿接口追问。无模型 Key 时仍可完成预写的追问，不让模型决定剧情是否通关。
4. 结尾：展示本次选择、所用证据、仍待核对的点，允许从入口重玩另一角色。可选生成本机手册，个人推测与资料线索始终分开。

两个结尾可为“形成有依据的临时解释”和“保留问题，约定继续核对”。结尾只描述过程状态，不给学习能力评分；现有关键词匹配不能判定真假。没有可靠资料时，不能把继承资料设为唯一正确答案。

## 90 秒课堂演示脚本

| 时间 | 实际操作 | 观众能看见的变化 |
|---|---|---|
| 0–15 秒 | 选观察员，接受一张待核实导览卡 | 数字人提出具体观察任务 |
| 15–35 秒 | 手动打开证据卡；P1 验收后可改为手机扫描卡 | 出现线索及来源状态，游客主动收下 |
| 35–55 秒 | 在“补充观察/查资料”中选一个，写一句自己的解释 | 故事进入相应分支，显示证据与个人推测的区别 |
| 55–75 秒 | 点击带问题问数字人，核对后修订记录 | 草稿经用户确认发送；离线用预写提示继续 |
| 75–90 秒 | 打开选择回放，切换角色重玩 | 展示另一种问题路径和仍未解决的问题 |

AR 是这段演示的增强入口；没有摄像头、权限被拒、网络/设备失败时，同一张卡手动打开并继续，不以假扫描动画冒充真识别。

## 三阶段交付与验收

### 第一阶段：一幕可重玩的故事（P0）

范围：锁定 inkjs 版本和许可证，源码 `.ink` 与预编译 JSON 一起管理；运行时资源随 Spring Boot 静态服务提供，课堂不用临时访问公共 CDN。单设备、两角色、三决策节点、至少两个可达结尾；先用原创课堂资料。不接任意用户上传脚本。

接口边界建议：一个故事适配器封装 Story，暴露当前段落、可选项、选择、重置、快照恢复。故事配置与素材清单带 storyId/version/evidenceId；不直接执行包内 HTML。engine 状态和个人观察分开存，损坏/旧版存档可以清除故事进度，不能清掉观察笔记。进一步 API、schema 和 REQ 编号在实施票内细化。

验收：相同选择可复现；两种角色确实进入不同问题；重置只重置本故事；刷新恢复经过校验的进度；非法索引/旧版/损坏状态不崩；两结尾自动遍历；草稿不覆盖不自动发；移除 Key 仍完成故事。页面适配手机与键盘，故事文字使用 textContent。运行 Node 行为测试、Maven verify、文档链接和隔离 HTTP 冒烟。

### 第二阶段：实体证据卡 AR（P1，依赖第一阶段）

只做两张原创图像卡及其 `.mind`，一台手机；先验真实图像跟踪，再加入故事。单独按需启动 AR 页面，避免同屏叠加 Haru 与 AR 的 GPU 负担。检测到卡仅展示线索，点击才写入故事。关闭页面停止媒体轨道、销毁渲染资源；权限拒绝、丢失目标和不支持设备均可手动继续。

验收：在实际演示手机上通过可信 HTTPS 页面启动摄像头；两张卡能对应不同 evidenceId；重复识别不重复收集；离开后摄像头停止；失败可手动完成 P0。记录手机/浏览器、光照、卡片尺寸和实际表现；桌面自动测试不能替代真机扫描。普通手机访问电脑的 HTTP 局域网 IP 不作为摄像头成功方案。

### 第三阶段：双人证据板可行性验证（P2，依赖第一阶段）

先用两设备验证互补线索玩法，再决定是否引入 Yjs。若只是“各自交一张完整卡”，普通受控服务端事件可能足够；确有同时编辑/断线合并需求再选 CRDT。

如用 Yjs，共享范围只含显式加入的证据板，私有笔记和聊天不进入房间。用受控服务端而非公共演示 provider；定义邀请/退出、房间归属、来源标签和保留期限，鉴权不能只看客户端传来的用户名。不要把双方秘密线索放进一个所有人都能同步读取的文档。

验收门槛：两设备同房协作可见，跨房/未授权读写拒绝；掉线恢复不重复卡；撤销/删除边界清晰；退出后停止同步。没有这套验证不宣称多人功能完成。

Pannellum 等拿到至少一张自摄或明确授权的全景，再建实施票；Transformers.js 等具体离线需求和基准样本，再做模型选型。两者不列为本阶段必须交付。

## 三人分工建议及开源贡献证据

| 角色 | 具体交付 | 可核验的原创证据 |
|---|---|---|
| A 交互与叙事 | 故事适配器、回放和数字人交接 | 两路径录屏、交互稿、自己的 PR |
| B 内容与验证 | 原创剧本、资料核对、故事分支遍历测试 | `.ink` 源码、来源表、结尾用例 |
| C AR 与集成 | 两张原创卡、目标编译、失败回退与真机验收 | 卡片源图/许可、扫描录像、设备记录 |

分工仅为建议，不能代替成员实际认领。每个库记录精确版本、上游地址、LICENSE/NOTICE 和修改项；素材分别记录作者与授权。研究不意味着已经取得老师资料、Live2D 模型或景区图片的再分发许可。
