# 游览导演与游客体验 Implementation Plan

**Goal:** 按用户确认的三个目标，交付可解释行程、可衔接观察体验及统一前端优化。
**Architecture:** 新增纯JS规则规划模块及DOM适配器；复用现有景点API和GuideChatDraft、观察内容包。扩展现有绿色/纸白色界面，不改动后端鉴权接口。
**Spec:** 用户本轮确认“三个都要”；议题验收条件和docs/director_design.md。

## 一、最高优先级：游览导演

- [x] 时间预算（30/60/90分钟）、同行人、兴趣、晴/雨情境输入；生成1–4站计划和逐站理由。
- [x] “时间减半/雨天备选”重新编排，明确显示保留/移除与原因；可恢复原预算。
- [x] 时长标明课设停留估算、不含步行排队、不保证实际开放；雨天是手动情境。
- [x] 每站支持准备导游草稿和打开当前内容包对应观察任务；不自动发请求或切换内容包。
- [x] 规则边界、预算、无匹配、重编排、HTML安全、草稿冲突和无对应任务测试。

## 二、观察体验

- [x] 明确当前任务、观察/解释提示、已保存记录；从行程聚焦本站，保留未保存草稿。
- [x] 导入其他内容包后站点无对应任务时给出明确反馈，不替用户换包。
- [x] 保留个人观察与资料分离、手动记录模式、存储失败反馈。

## 三、前端美化

- [x] 首页清晰导航、行程控制区、观察工作区、景点索引；压缩装饰，改善留白与排版。
- [x] 卡片改为可读景点索引，数字人缩小并保持可触达；聊天和手机版不遮挡主要控件。
- [x] 键盘焦点、reduced-motion、loading/error/empty反馈和小屏无横向溢出。
- [x] 实际浏览器桌面/手机截图、技能检测器、独立设计与代码复查；Maven/Node/HTTP/文档检查。

## 文件

新建director-core.js、director.js、tour-experience.css及其测试；修改index.html、main.js景点渲染、exploration.js聚焦接口；文档记录需求、设计、API复用、验证和进度。
