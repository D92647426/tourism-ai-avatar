# REQ-037 自然提问的实体、别名与知识检索（GitHub #10）

## 目标与取舍

让游客用自然句子和常用简称找到相关的本地知识，明确资料未命中和歧义，候选条目可追溯。沿用 Java 8 / Spring Boot 与 JSON，无新依赖、不使用付费模型验证核心检索。用户已持续授权按议题自主开工，本轮由 Codex 决定实现细节并执行；额度300分钟窗口剩余92%，未启用 DeepSeek 默认分工。

保留整句子串会继续漏掉自然提问；向量库与模型识别超出本议题。采用人工维护景点别名、已有知识关键词和确定性排序，容易离线验收。不是语义搜索、不是史料事实核验，也不是多轮指代解析（后者属于 #11）。

## 接口与规则

1. 独立 KnowledgeRetriever 模块负责纯匹配、排序和上下文预算；KnowledgeService 管文件/CRUD，提供一次检索快照，旧 retrieveRelevantContext(String) 入口继续可用。后台 search(String) 保留原来的管理搜索行为。
2. 人工别名字典在打包资源 retrieval-entities.json，覆盖16个现有景点的正式名/常用简称，包含明确排除的外景名称，防止“乐山大佛”等词中的“大佛”误归为灵山大佛。字典不绑定知识ID，避免用户自定义库复用ID时串条目；维护时不得假造景点事实。
3. 用 NFKC、小写、空白/标点规范化处理问题。显式实体优先：标题命中优于关键词、正文顺带提及；无实体时按原知识的逗号分隔关键词与完整标题匹配。避免凭“它/故事/那个寺庙”等泛词猜景点，也不从每两个汉字随意推断实体。
4. 先稳定评分，再以ID升序打破平分；多个显式实体优先各给一条最相关候选，最多3条。单条正文最多200字符、标题最多80字符、总知识上下文最多1200字符。只给被实际纳入上下文的条目返回引用；空/无关/含糊提问无命中时返回空上下文，不截取原列表前三条。
5. 上下文保留【知识库参考资料】和正文前部的“待补充/未核验”提示；附本地资料 K{id} 标识。ChatResponse 新增 knowledgeReferences 数组，元素为 id、title、source（local-knowledge:{id}）。这是本次提供的候选参考，不代表模型实际采用、更不代表官方出处或核验结果。
6. ChatService 一次检索的结果用于模型上下文与降级，不重复检索混入不同快照。离线可识别简称；单景点保留景点字段回答并附对应知识，多景点不简单选原列表第一项；缺资料明确说明，指代/泛问引导补充名称。既有聊天字段、路线/问候/票价/交通规则仍可用，变动资料保持课程示例标识。
7. 原始知识16条和景点16个ID不变，不扩写知识正文，不读取用户历史，不引入认证/会话变更。基于 #21 的 c7a5351，PR以 codex/issue-9-knowledge-integrity 为目标；先合并 #21，再调整本PR到main。其他待合并PR不在本分支。

## 验收

- 至少十个真实默认库问题，分别验证检索和离线最终回复；包括全名、简称、外景同名、多个景点、空白、无关和含糊指代。
- 构造次序打乱的自定义库验证平分稳定、ID不当实体映射；超长标题/正文验证预算与引用一致；待补充提示不丢失。
- 模型请求用本机 HTTP mock 检查参考上下文和引用，没有调用真实模型时如实记录。
- Java全套、数据检查及其Python测试、文档链接、空Key隔离HTTP smoke通过；不把景点降级命中冒充知识检索成功。
