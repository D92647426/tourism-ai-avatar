# REQ-053 本地角色声线（API-053 / TEST-053）

用户已确认使用本地试听声线并要求接入。文字接口不变：先展示完整文字，随后逐句生成语音。文本流式回复不在本轮。

## 接口与边界

- 声线标识 `local:character`，加入现有管理员下拉框，默认配置选用该标识；已保存的系统声线选择保持有效。使用同一音量、语速和回听入口。
- 浏览器新引擎按中文标点和最多80个 Unicode 字符切句，依次请求当前句并预取下一句，使用真实 HTMLAudio playing/ended 事件驱动生命周期。等待下一段时关闭嘴型。停止、后台、关闭面板、新问题须取消请求、音频和对象 URL；旧事件失效。
- POST `/api/speech/synthesize`：登录+CSRF，JSON `{text,speed}`，text=1–80个 Unicode 字符，speed=0.5–2有限数。成功200 `audio/wav`，`Cache-Control: no-store`。400输入错误，401/403身份/CSRF，503禁用/繁忙/不可用，502上游错误，504超时。响应不得包含配置路径、异常详情或用户文案。
- Java 仅向服务端配置的 HTTP loopback 地址请求，不接受用户 URL，不跟随重定向；连接800ms、读取12秒、响应最多4MiB，同时最多2个请求。不得把语音请求作为聊天写入历史。
- Python 标准库本地工作进程，固定监听127.0.0.1，载入外置 GPT-SoVITS 与已校验模型，启动时预热。最多2个请求（1推理+1等待），状态接口不泄露路径。无训练WebUI、无模型文件入Git、无在线付费配音。
- 新语音失败时从未完成句回退系统声音，不重复已完成句；浏览器拒绝自动播放时提示点击回听，不擅自循环重试。音量0保留静音。Android原协议继续原回退策略。
- 常驻服务解决冷启动，不保证端到端2.4秒；此前数字只是不含LLM、网络、解码的单次语音引擎基准。

## 验收

真实本机角色模型走网页聊天和回听；文字先于音频显示，嘴型只随真实播放，停止无残音。关闭服务后系统声音回退，前段播放后失败不重复已完成句子。验证分句、预取、取消/迟到事件、播放拒绝、语速/静音、401/CSRF、非法输入、超时/响应体上限、并发限制、无上游信息泄露及无聊天副作用。
